## O1の点検

導入後、公式JV-Linkから保存した1件の生レコードについて実行できる。

```powershell
.\.venv\Scripts\python.exe -m shibata.ingestion.jv_o1 --input data/raw/one-o1.bin --output outputs/o1-inspection.json
```

CRLFを含む1レコードをそのまま渡す。複数レコードを結合したファイルは未対応。
すべての28スロットと特殊値の状態を保持し、無投票・取消を0倍として変換しない。
上限打切りはcappedと記録する。予測用入力へ自動的に昇格させない。
O1の発表時刻の年は自動補完しない。出力は常にprediction_ready=false。
削除・中止・最終などのデータ区分を保持し、スナップショットの有効性は別途確認する。
複勝・枠連・票数部分は未解析。実データの完全なO1適合検証器ではない。

## 導入後に順に確認すること

1. JV-Linkの導入日を記録し、対応ビット数・公式サンプル・Python環境を確認する。
2. 公式検証ツールで少量取得できることを確認する。
3. 実通信アダプターを追加する。JVReadの終了・ファイル切替・待機・エラーを区別し、終了時はJVCloseする。無限リトライしない。
4. 原文バイト列、元ファイル名、取得開始・終了時刻、要求条件、ハッシュを保存する。
5. RA/SEによる出走表・馬の識別・結果を確認し、O1と対応付ける。結果を予測入力へ混ぜない。
6. 時刻証拠と特殊ケースを確認して内部形式へ変換する。
7. まず1レースを目視照合し、少量の複数レースへ拡張する。
8. 実データの期間・欠損・公表時刻を確認した後、Phase判定と評価期間を確定する。

無料体験を開始するための導入・規約同意は、このオフライン作業には含まれない。

## バイト配列取得とRA/SE監査（2026-09-21追加）

JVRead文字列を再符号化する試験方式では日本語を含むSEのバイト位置が崩れたため、以降の小規模取得にはJVGetsを使う。64bit JV-Linkが導入済みのPowerShellで実行する。出力先は毎回新規にする。既存のprobe系スクリプトは診断用であり再利用しない。

```powershell
./scripts/collect-jvlink.ps1 -DataSpec 0B15 -RaceKey 2026092006040608 -OutputDirectory data/raw/example-new-capture
.venv/Scripts/python.exe -m shibata.ingestion.jv_race --race-dir data/raw/entries-bytes-20260921 --odds-dir data/raw/verified-20260921-nakayama08-odds --output data/raw/entries-bytes-20260921/audit-new.json
```

例の過去レースは提供期間内でのみ取得可能。監査はRA/SEの限定列とO1単勝部分を対象とし、HRを含む他種別は解析しない。取消・同着等を通常の教師ラベルへ自動変換しない。EOFだけでは同時点の一貫した応答と認定しない。manifest照合は監査CLIで必須となった。公開時刻の証拠確認は別途必要。

参考: [公式JV-Data仕様書](https://jra-van.jp/dlb/sdv/sdk/JV-Data4901.pdf)、[公式0B15整合性に関する回答](https://developer.jra-van.jp/t/topic/1035)、[JVGetsの公式導入説明](https://jra-van.jp/dlb/sdv/ml/20041020a.html)。

2026-09-20中山8Rの0B12を追加取得し18レコード（RA1、SE16、HR1）を保存。取得済み0B41の178件とmanifest検証・頭数・馬番号・順位の対応確認に成功した。正常16頭の結果を確認したが、当時の出走表の公表時点を証明するものではなく、学習入力への昇格はまだ行っていない。

同梱JV-Link仕様書4.9.0.1の17〜19ページで、JVOpenは提供時刻の開始・終了を指定できることを確認した。これはレース開催日による範囲指定ではない。通常データoption=1とセットアップoption=3/4は区別する。option=4でも初回ダイアログがあるため、無人での初回大量セットアップは行わない。

上記診断に-Captureオプションを追加した。対象20ファイル・申告容量10MiB以内の場合に限り、90秒/5000レコード上限でJVGetsを読み、原本・取得時刻・元ファイル名・SHA256を保存する。JVOpen内部の同期呼出し自体の時間上限ではない。完了前の停止はcomplete=falseとして学習利用しない。

実取得: 提供期間20260920000000-20260920235959、RACE、option=1で3ファイル/230KB、688レコードを取得しEOFとJVClose=0を確認。JG344、RA24、SE320。RA/SEはすべて区分2、開催日は20260921であり、結果レコードではなかった。全688件のサイズ・SHA256・CRLF・保存ファイル集合を点検済み。これは「9/20開催の成績」を取得したことにはならない。
