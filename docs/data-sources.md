# データ取得の調査メモ

確認日: 2026-09-21。取得元は未確定。契約や有料申込は行っていない。

## 第一候補: JRA-VAN Data Lab.

[公式SDK案内](https://developer.jra-van.jp/t/topic/45)では、2026-08-04版のSDK 5.0.0に64bit版とPythonサンプルが掲載されている。SDKサンプルのPython版と、本プロジェクトの分析環境Python 3.12の互換性は未検証。JV-Linkの導入・接続試験は別途必要。

[公式FAQ](https://jra-van.jp/dlb/sdv/faq.html)によると時系列オッズは履歴を取得して必要なレコードを選択する方式。履歴提供期間と、実際に取得できる過去年・時刻は最新仕様書と取得結果で確認する。長年分の発走10分前オッズが取得できるとは仮定しない。

[利用規約](https://jra-van.jp/info/rule.html)の第7条に情報の利用範囲、第9条にJV-Link以外からのData Lab.サーバアクセスに関する制限がある。取得は公式JV-Link経由とし、生データはGitHubへ公開しない。

## 既存CSV / Parquetがある場合

取得元、利用条件、対象期間、列定義、出走取消・同着・返還の扱いを確認する。
ファイルだけで時点整合性が証明できるとは扱わない。

## 実データ受入れ前の確認事項

- 1行の単位、race_idとhorse_idの定義、重複、文字列IDの桁落ち。
- レース予定時刻、予測締切時刻、情報の提供時刻、ローカル取得時刻を区別する。
- 過去に提供された時刻を示す証拠と、後日取得した時刻を混同しない。
- 最終オッズを発走前オッズの代替として使用しない。
- 結果・払戻は評価用に分離し、特徴量への混入を防ぐ。
- 同着、取消、競走中止、開催中止、オッズ欠損の扱いを決めて記録する。
- 対象期間の欠損・更新履歴を確認してからTrain/Validation/Test期間を確定する。
