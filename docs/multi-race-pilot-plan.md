## 成功したレースだけを選ばないための台帳

全予定対象に一意のrace_idを付け、予定発走、締切、試行時刻、予測ファイルのハッシュ、結果取得・評価のハッシュと状態を記録する。状態はPLANNED / CAPTURE_FAILED / INELIGIBLE / PREDICTED / RESULT_PENDING / EVALUATED等に分ける。ハードウェア停止・ネットワーク不通・締切超過も欠測として残す。欠測分を後日取得で発走前観測に見せない。

同一レースに予測を複数保存しても採用するのは事前ルールに合う一つのみ。重複を件数として加算しない。成績を理由に除外しない。

## 例外と集計の制限

現実装で未対応の中止、取消・除外、競走中止、同着、頭数/発走時刻変更、未確定結果、上限打切り、最新無投票などは分類して保留・除外件数を公表する。結果を見て馬を削除したり確率を再正規化しない。こうした除外があるため、指標は「受入条件を満たした完走レース群」の結果でありJRA全レースの性能とは言えない。

日別・全期間の対象数、予測成功数、評価成功数、理由別欠測・除外数、オッズの古さ、実際の締切・保存時刻を併記する。指標は行を結合して再計算し、頭数の違うレースの1頭あたり指標を単純平均しない。人気・オッズ帯・Calibrationは現在のv1集計を維持する。少数の区分には解釈上の限界を明記する。

先日の阪神1Rは締切が発走約285分前だったため、この10分前試験には混ぜない。配線確認の独立した実験として保持する。

## 今回整備した集計ツール

`python -m shibata.aggregate_saved --ledger <台帳JSON> --output-dir <新規フォルダ>`

台帳は評価対象を明示した配列。各項目はprediction_dir、prediction_status_sha256、evaluation_dir、evaluation_status_sha256。相対パスは台帳ファイルの位置から解決する。statusと全出力のハッシュを確認し、各評価値を保存済み予測とラベルから再現してから全行を集計する。重複・破損・不一致は全体を停止し、問題のある実験を黙って捨てない。

aggregate_saved単体は記述的な集計までで、population_coverage=unknown、fixed_cutoff_verified=falseを維持する。正式な日別試験には追加したpilot reportを使い、凍結した全対象台帳と承認条件への適合も検査する。開催場の網羅性は元資料の確認が前提で、自動認証ではない。

PC/JV-Link/ネットワークが動いていることが収集の前提。自動起動・スリープ制御・タスク予約は別作業であり、今回の設定ファイルだけでは動かない。
