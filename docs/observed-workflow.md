# 発走前の観測データから市場ベースラインを作る

この経路は発走前にローカルで実際に取得した入力の診断用。学習モデルでも、固定した「発走10分前」モデルでもない。対象期間・正式な予測締切は未設定。

## 実行

JV-Link導入済みの64bit PowerShellで、対象レースの正しい16桁キーと毎回新しい出力先を指定する。

```powershell
./scripts/collect-jvlink.ps1 -DataSpec 0B15 -RaceKey <レースキー> -OutputDirectory data/raw/<取得ID>-entries
./scripts/collect-jvlink.ps1 -DataSpec 0B41 -RaceKey <レースキー> -OutputDirectory data/raw/<取得ID>-odds
.venv/Scripts/python.exe -m shibata.observed --entries-dir data/raw/<取得ID>-entries --odds-dir data/raw/<取得ID>-odds --prediction-at <取得完了後かつ発走前のタイムゾーン付き時刻> --output-dir outputs/<実験ID>
```

山括弧は実際の値へ置換する。両取得が成功したことを確認してから計算する。`prediction-at`は実行時点より未来に設定できない。取得失敗・未配信・中止を正常な空データに置き換えない。

出力はraces.csv、entries.csv、odds.csv、predictions.csv、status.json。最後に実行状態、入力manifestと出力・PythonコードのSHA256、計算時刻、発走前に計算したかを記録する。過去入力の再実行は可能だが、発走後に計算した出力をリアルタイム予測実績とは扱わない。結果の読み込み・評価・投票は行わない。

## 受け入れ条件

- JVGetsで正常終了した取得manifest、実ファイル集合、バイト数、SHA256、対象レース、タイムゾーン付き時刻とその順序が一致すること。旧試験方式のmanifestは受け入れない。
- 全取得の完了が指定締切以前、締切が取得したRAの予定発走時刻より前であること。
- RA/SEは区分2のみ。単一の一貫した版、馬番号・登録番号の一意性、登録数・出走数・取得頭数が一致すること。
- O1は区分1の中間オッズ、発売あり、全頭の正常な単勝値・人気があること。前日最終・最終・確定・取消・無投票・上限打切り等は未対応として停止する。
- 発表月日時分はレース当日または前日に一意に対応する場合だけ日本時間へ変換し、取得時刻以前であることを確認する。年越しもこの二日から解決する。範囲外を推測しない。
- 同一発表時刻に複数版があるときや最新スナップショットが不完全なときは停止する。古い正常値への自動後退はしない。

availability列には取得によって知り得た時刻を保守的な上限として使う。配信元の正確な公表時刻とは異なる。ハッシュは改変検出のための自己整合性検証であり、PC時計の正確性や悪意あるmanifest書換えを第三者が証明するものではない。発走変更・取消等の更新追跡、独立した時計検証、原本の第三者時刻認証は未実装。
