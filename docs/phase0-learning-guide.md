# Phase 0の最小演習

これは開発環境・基本操作を確認する教材。実競馬の予測性能や、ユーザー本人の習熟度を認定するものではない。notebooks/phase0-foundations.ipynbとphase0_completion CLIを対応させて読む。

## Pythonとデータ処理

Notebook最初のセルのStudyRunはclassの例。nameとsyntheticを持つ値のまとまりを定義し、インスタンスごとに値を保持する。runsはlist、describeはfunctionで、dictを返す。forで繰り返し、ifで条件分岐し、例外をraiseして不適切な入力を拒否する。try/exceptは想定したエラーだけを捕捉する。これらは本番処理でも検査・記録の基礎になる。

NumPyは数値配列と計算、pandasは列名・型を持つ表を扱う。CSVは型が失われやすいのでID列の文字列指定が必要。Parquetでは型も保存されるが、実際に往復一致を検査する。集計はgroupby、表の結合はmerge、並べ替えはsort_valuesを使う。many-to-one検査は、結合先の重複で行が増える事故を検出する。

shift(1)で現在行を除き、その後rolling(2)で過去2回の平均を取る。先にrollingだけを使うと当該行の結果が混入する。初回の過去成績は欠損であり、勝率0とは意味が違う。全期間の勝数集計は説明用で、過去の予測特徴量には使わない。SQLiteのGROUP BYとpandasの集計が一致することもCLIで確認する。

## 図とNotebook

matplotlibのfigureは図全体、axesは描画領域。軸名、対象期間、単位を付ける。今回の線グラフは架空の馬の過去履歴で、的中率や収益の図ではない。初回の履歴欠損は0として描画しない。

Notebookは説明と実行セル・出力を一緒に置く文書。途中実行に依存しないよう、カーネルを再起動して上から順番に実行する。受入CLIは指定venvのPythonで全セルを実行し、出力付きのコピーを新しいoutputsフォルダに保存する。Gitには出力なしの教材だけを保存する。

## 学習ライブラリの役割

- scikit-learn: 前処理、モデル、評価を共通のfit/predict等の操作で扱う。前処理のfitも学習側だけで行う。
- LightGBM: 決定木を順に追加する勾配ブースティングの実装。深さや葉数を増やすと過学習しやすくなる。
- CatBoost: カテゴリを含む表データにも使う勾配ブースティングの実装。導入確認では小さな数値データだけを使う。

今回の3種類のfit/predict_probaは、インストールとネイティブライブラリ・確率出力の動作確認だけ。実競馬モデルの比較・採用・チューニングではない。固定乱数、単一スレッド、16行の人工学習入力と4行の別入力を使う。

git statusで対象を確認し、git diffで差分を読む。検査したコード・設定・説明をgit addし、git commitで変更理由を記録する。git pushで承認済みGitHubリポジトリへ共有する。生データ、認証情報、環境フォルダ、生成モデルは追加しない。
