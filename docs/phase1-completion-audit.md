# Phase 1の完了条件と残タスク

確認日: 2026-09-23。計画書第4章・第24章、現在の実装、保存済み実験記録を照合した。今回はタスクの洗い出しであり、新しい取得・学習・観測条件変更は行っていない。

## 結論と完了の範囲

市場確率の計算と評価処理は実装済み。残る中心作業は、承認済みの発走10分前観測を実行し、全対象の欠測と利用時点の証拠を含めて集計し、6項目の終了判定を記録すること。

計画書の完了条件は「オッズだけのモデルの性能を数値として保存する」。市場を上回るモデル、利益、追加の学習期間、任意の最低レース数はPhase 1の条件ではない。既存の1レース評価で数値保存の経路は確認できているが、これだけで較正の良さや一般的な性能を認定しない。

現行の承認済み実験を最後まで実施する場合、全体の終了判定は2026-10-04の結果確認後となる。これは承認済み4日間の実験予定によるもので、計画書が一律に4日間の待機を要求しているわけではない。日程終了だけで自動的に全PASSとはしない。

対象は9/26・9/27・10/3・10/4、JRA平地全場。予測締切は正式発走時刻の10分前、締切時のオッズ経過は5分以内、保存は締切後1分以内。設定・v1指標は変更しない。この観測試験を機械学習の最終Testに流用しない。

## 残タスク：実施順

| 順番 | 作業 | 完了を確認する成果物 | 実施時期 |
| --- | --- | --- | --- |
| 1 | 終了報告の様式・照合手順を準備する | 下記6項目の判定欄、日別・全期間の対象数、欠測理由、指標、標本数、制約を記載する報告テンプレート | 今できる |
| 2 | 4日分をまとめる手順を整える | 日別台帳を漏れなく照合する手順、重複のない評価一覧、全行再計算と締切証拠への参照。合成の欠測例・重複例でも確認 | 今できる |
| 3 | 正式出馬表から日別台帳を固定する | 全開催場・全レースの正式時刻、出典・確認時刻、対象外の障害競走も含む固定台帳。取得枠の競合検査結果 | 各日の公式情報公開後 |
| 4 | 当日の観測を実行する | Windows時刻同期の確認記録、runnerの起動成功と単一起動の確認、期限内保存済み予測、取得時刻・オッズ時刻・保存時刻。失敗も台帳に残す | 各開催日の朝〜発走前 |
| 5 | 結果を取得し、予測を変更せず評価する | runner終了後の`pilot_finish`結果。未確定・欠測・除外理由を全対象について記録し、未確定結果を後日再確認 | 各日の取得終了後、必要な後続確認 |
| 6 | 全期間を集計・再現確認して終了判定する | 4日分の対象照合、評価指標・較正表・人気別・オッズ帯別の表、標本数、再現手順、6項目の最終判定を保存 | 全観測と結果確認後 |

手順2の注意: 既存の`aggregate_saved`だけでは、入力一覧から漏れたレースが分からない。実装上も`population_coverage=unknown`、`fixed_cutoff_verified=false`を返す。各日`pilot report`の固定台帳・締切検証結果と組み合わせる必要がある。日別指標の単純平均で全期間指標を作らない。新しい専用CLIを必須とせず、既存処理を使った再現可能な手順でもよい。

手順3の注意: 現時点でローカルの正式日別台帳は未作成。全開催場の確認は入力の自己申告だけでは証明できず、公式出馬表との照合が必要。公開前の反復取得はしない。

手順4の注意: 毎日9時・17時の定期確認は厳密な実行時刻を保証しない。締切はローカルrunnerで制御する。各開催日の起動成功確認が必要であり、PCを開けているだけで取得成功とは判定しない。締切後の予測作成、期限延長、確定オッズによる欠測補充は禁止。

## 6項目の終了判定で確認すること

これは最終判定時の確認事項であり、現時点の全PASS宣言ではない。

| 項目 | 確認事項 | 現時点の残り |
| --- | --- | --- |
| DATA | 全対象の所在・状態・欠測理由が分かり、評価対象の馬・レース・結果が一致する | 正式台帳と4日分の実データ照合 |
| LEAKAGE | 評価に使う予測が承認済み時点の情報から期限内に保存され、結果取得後に再生成されていない | 当日時刻同期、鮮度・保存時刻・原本ハッシュの証拠確認 |
| CODE | 同じ保存済み入力・設定から同じ指標を再現できる | 全期間の集計手順と再計算確認 |
| TEST | 締切・重複・欠測・改変等の防止処理が検証されている | 集計手順で追加する処理があれば対応する検証。既存227件の記録を参照 |
| VALIDATION | 結果未知の時点に保存した固定市場確率を後の結果で評価し、標本数・観測範囲を明示する | 承認済み観測の評価。学習モデルの未知期間性能や最終Testを認定しない |
| DOCUMENTATION | 特徴量台帳、設定、データ版、対象数、全指標、例外、制約、再現方法と判定が揃う | 最終実験記録・終了記録 |

欠測ゼロを新たな必須条件にはしない。ただし取得できたレースだけを黙って母集団と扱わず、欠測による偏りと評価の限界を説明する。評価可能なレースがゼロなら性能評価は未完了。少数の区分を十分な較正証拠とみなさず、未解決の利用時点違反や整合性エラーをPASSにしない。追加観測が必要と判明した場合も、成績を見て期間を無断延長せず、必要な条件変更を別途提示する。

## 今回追加しない作業

- 機械学習モデルの追加・強化、特徴量の追加、参考実験の月別拡張。
- ROIや買い目、収益性の判定。
- 数年分のデータ取得や本番サービスの構築。
- 観測日の追加、指標変更、最終Testの利用。

現在の残タスク整理のために、ユーザーの追加操作や新たな契約は必要ない。開催日の稼働維持は既に承認済み。実行時に利用資格・認証・インストールの問題が発生した場合に、必要な操作を具体的に案内する。
