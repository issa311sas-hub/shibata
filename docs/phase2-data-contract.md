# Phase 2実データ入力の受入条件（準備案）

2026-09-23。新しい特徴量、期間、指標の承認ではない。既存の`logistic-initial-v1`の9特徴量、Train=2025-10〜2026-06、Validation=2026-07〜08、Test=2026-09-01〜13を前提に、将来の実データ評価で誤って事後情報を使わないための検査項目を整理する。

## レースごとに必要な証拠

| 対象 | 必要な内容 | 不足したとき |
| --- | --- | --- |
| 日時と対象 | JRAの正式発走時刻、会場・レースID、平地/障害、登録頭数・全馬ID | 対象を未確定とし学習・評価へ入れない |
| 予測用原本 | RA/SEなどの提供時点が分かる原本、取得manifest・原本SHA256、局所取得開始/終了時刻 | 事後版からの推測だけで利用時点をPASSにしない |
| 利用可能性 | 各入力の観測時刻が指定された締切以前。改訂・馬番・距離・斤量・頭数の一致 | 変更前後を黙って混ぜず、理由を記録して対象から外すか保留 |
| オッズ比較 | 対象レース全馬の同じ締切条件を満たす単勝オッズ、時刻・原本SHA256 | モデルと市場の同一時点比較は保留。確定オッズで代用しない |
| 結果ラベル | 発走後に取得した結果原本、全頭とのID照合、勝馬1頭の確認、未確定・同着・取消等の理由 | 欠測・例外を台帳へ残し、0埋めしない |
| データ版 | 原本・特徴量・ラベル・分割・モデル設定と出力のハッシュ、処理コード版 | 再現性をPASSにしない |

特徴量の具体的な式、出典、利用可能時刻、欠損率、リーク危険度など13項目は[特徴量台帳](feature-registry.md)で管理する。結果由来の着順を予測用入力へ渡さない。Train/Validation/Testはレース単位で日付順に分け、前処理とカテゴリ集合はTrainのみから学習する。Test結果をモデル選択へ使わない。

## 現在のデータとの関係

- Phase 1の9/26・27、10/3・4観測は上記の承認済みTrain/Validation/Test期間の外にある。したがって、その4日分だけで当初のPhase 2分割を満たす学習・検証データにはならない。期間を変更する場合は、実行前に条件を明示する。
- 既存の過去成績参考実験は最終RA/SEから9項目を復元したもの。当時の利用時点を証明できず、結果を用いた採否判定による偏りもある。厳密な実験の入力に無条件で昇格させない。
- 9/21阪神1Rで観測したRA/SE/O1は利用時点の接続確認になるが、1レースで学習期間全体や一般的性能を代表しない。
- 架空のJV形式原本を使う`phase2_rehearsal`は、パーサーから3モデル評価までの操作確認。合成manifestの時刻は人工値であり、実際のJRA公表時刻・PC時計の正確さを証明しない。

## 正式実験へ進む前の判定

入力候補を全件一覧にし、各レースに対象日・原本SHA256・取得時刻・特徴量の利用可否・分割・ラベル状態・市場比較の可否を付ける。未取得日は0件の対象と決め付けず、データ範囲として別に報告する。証拠が揃わない場合は参考実験と厳密評価を分けて記録し、Phase 2のLEAKAGE / VALIDATIONをPASSにしない。

正式な3モデル比較では、同じレース・馬・市場時点・v1指標を使う。Phase 1の市場基準の対象と異なる場合は、両者の数値を直接優劣比較しない。次に必要なデータ取得や期間変更がある場合、その条件と理由を先に提示する。
